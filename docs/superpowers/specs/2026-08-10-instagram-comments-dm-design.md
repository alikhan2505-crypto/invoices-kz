# Instagram comments & DM auto-reply — дизайн

**Статус:** одобрено, готово к написанию плана.

## Проблема

Сейчас автоматизация Instagram (`src/lib/instagram.ts`, `instagram_drafts`) умеет только публиковать посты через
Telegram-одобрение. Приёма событий ОТ Instagram — комментариев под постами и личных сообщений (DM) — нет вообще:
ни вебхука, ни соответствующих прав в Meta App, ни какой-либо логики ответа.

## Цель

Автоматически отвечать на комментарии и DM: быстрым шаблоном, если вопрос предсказуемый (по ключевым словам), и
AI-сгенерированным черновиком с обязательным одобрением в Telegram — во всех остальных случаях. Все AI-ответы
логируются для последующего разбора и добавления новых шаблонов.

## Предпосылка (проверено вживую 2026-08-10)

Приложение `invoices.kz-IG` (App ID 1763701871429757, режим «В разработке») уже имеет сценарий использования
«Instagram API» с добавленными правами `instagram_business_basic`, `instagram_business_manage_comments`,
`instagram_business_manage_messages` — Meta App Review не требуется, так как приложение в Development-режиме, а
Instagram-аккаунт уже добавлен с ролью «Тестировщик Instagram». Не хватает только: (1) сгенерировать новый токен
доступа с этими правами (текущий `INSTAGRAM_ACCESS_TOKEN` в проде выпущен раньше и их не имеет), (2) зарегистрировать
вебхук (URL + verify token), (3) опубликовать приложение — все три пункта делает пользователь сам, после того как
код вебхука будет готов (см. «Раздел E» ниже).

## Архитектура

Новый отдельный вебхук `/api/instagram/webhook` — отдельный от существующего `/api/instagram/telegram-webhook`
(тот слушает события ОТ Telegram, этот — события ОТ Instagram/Meta, у них разная платформа и разный механизм
верификации). Обрабатывает:
- **GET** — верификационный хендшейк Meta (`hub.challenge`), отвечает тем же значением после сверки
  `hub.verify_token` с секретом.
- **POST** — реальные события (`comments`, `messages`), тело подписано `X-Hub-Signature-256` (HMAC от App Secret) —
  проверяется перед обработкой, аналогично тому как уже проверяется `x-telegram-bot-api-secret-token` для
  Telegram-вебхука, только другим механизмом (подпись всего тела, а не константный заголовок).

Поток обработки входящего события:
1. Проверить тумблер `instagram_autoreply_settings.paused` — если включена пауза, залогировать и выйти без ответа.
2. Проверить `external_id` (ID комментария/сообщения от Instagram) в `instagram_auto_replies` — если уже есть,
   выйти (защита от повторной доставки одного и того же вебхука).
3. Найти совпадение по ключевым словам среди строк `instagram_reply_templates`.
4. **Совпадение есть** → сразу отправить `reply_text` шаблона через Instagram API, записать в
   `instagram_auto_replies` со статусом `sent`.
5. **Совпадения нет** → сгенерировать AI-черновик (текст входящего сообщения + автор + подпись поста, если есть,
   на вход модели) → отправить в Telegram (тот же чат, что для постов) с кнопками
   **✅ Отправить / ✏️ Изменить / ❌ Пропустить** → записать в `instagram_auto_replies` со статусом `pending_review`
   и заполненными `telegram_chat_id`/`telegram_message_id`. Публикация ответа происходит только после действия в
   Telegram (обрабатывается расширением существующего `/api/instagram/telegram-webhook`, тем же паттерном, что уже
   работает для `ig_publish`/`ig_reject`).

Отправка ответа в Instagram:
- Комментарий: `POST /{comment-id}/replies`, параметр `message`.
- DM: `POST /{ig-user-id}/messages`, `recipient: {id: <ID отправителя>}, message: {text: ...}`.

Оба запроса используют новый токен (см. «Предпосылка» выше) — старый токен для публикации постов эти права не
подпишет.

## Область действия

Реагируем на комментарии/DM под **всеми** постами аккаунта, не только опубликованными через нашу автоматизацию
(включая старые/ручные посты) — Meta присылает вебхук-события по всему аккаунту сразу, без привязки к конкретным
записям в `instagram_drafts`.

## Модель данных

**`instagram_reply_templates`** — список шаблонов:
- `id` uuid pk
- `trigger_words` text[] — список триггер-слов/фраз
- `reply_text` text — текст ответа
- `created_at` timestamptz

**`instagram_autoreply_settings`** — ровно одна строка на весь (единственный) аккаунт:
- `id` uuid pk
- `paused` boolean default false — быстрый аварийный выключатель, останавливает и шаблоны, и AI одновременно
- `updated_at` timestamptz

**`instagram_auto_replies`** — общий лог и очередь на одобрение (по образцу `instagram_drafts`):
- `id` uuid pk
- `source` text — `'comment'` | `'dm'`
- `external_id` text unique — ID комментария/сообщения в Instagram, для защиты от повторной обработки
- `from_username` text
- `incoming_text` text
- `reply_text` text — итоговый (или черновой, пока не одобрен) текст ответа
- `reply_type` text — `'template'` | `'ai'`
- `template_id` uuid nullable — какой шаблон сработал (если `reply_type = 'template'`)
- `status` text — `'sent'` | `'pending_review'` | `'sent_after_review'` | `'skipped'`
- `telegram_chat_id` text nullable, `telegram_message_id` bigint nullable — только для `pending_review`/уже
  обработанных AI-черновиков
- `created_at` timestamptz, `resolved_at` timestamptz nullable

## Управление шаблонами

Новая страница в `/profile`, доступная **только администратору** (`profiles.is_admin = true`) — по тому же
паттерну, что уже используется на `/admin` (`if (!profile?.is_admin) router.push('/dashboard')`). Список шаблонов
(добавить/изменить/удалить триггер-слова и текст ответа) и тумблер паузы — на одной странице.

## Журнал AI-ответов

Простой список на той же странице шаблонов: что спросили → что ответили, для периодического просмотра и ручного
добавления новых шаблонов по повторяющимся вопросам. Без автоматического «превратить в шаблон» — ручное добавление
через обычную форму создания шаблона.

## Раздел E — Что делает пользователь вручную (после деплоя кода)

1. На странице **Настройка API для входа в Instagram** (Meta App 1763701871429757) — сгенерировать новый токен
   доступа (роль тестировщика уже назначена).
2. Обновить `INSTAGRAM_ACCESS_TOKEN` в Vercel Production новым токеном.
3. Вписать в поля **URL обратного вызова** и **Подтверждение маркера** значения нового вебхука (URL и секрет,
   которые появятся после того, как код будет написан и задеплоен).
4. Опубликовать приложение (сейчас в статусе «Не опубликовано» — обязательно для реальной доставки вебхуков).

## Вне рамок

- Никакой автоматической эскалации/аналитики тональности входящих сообщений — только ключевые слова для шаблонов.
- Кнопка «превратить лог в шаблон» одним кликом — не делаем, ручное добавление через форму.
- Ответы на посты, где комментарии физически отключены или удалены до обработки, — не обрабатываем отдельно,
  Instagram API в этом случае просто вернёт ошибку, которая логируется и не ретраится.
