# Публичный лендинг Kaspi Cashier API — дизайн

**Дата:** 2026-08-30
**Новый файл:** `src/app/cashier-api/page.tsx` (публичная маркетинговая страница, без авторизации)
**Затронутый существующий файл:** `src/app/kaspi-api/docs/page.tsx` (закрыть от публичного доступа)

## Контекст и цель

Founder вводит Kaspi Cashier API как отдельный продукт для другой аудитории — разработчиков/технических основателей, которым бухгалтерия invoices.kz не нужна вовсе. Ценовой брейнсторм этой же сессии (артефакт «Ценовая архитектура») зафиксировал: аудитория другая → нужна отдельная посадочная страница, отдельный визуальный язык.

Это блокирующая зависимость для отдельного проекта «Редизайн главного лендинга» (спека `2026-08-30-landing-redesign-design.md`), который уже ссылается на маршрут `/cashier-api` в футере и в списке фич — та работа не может быть выполнена, пока эта страница не задеплоена.

## Что уже существует (важно не дублировать)

- **`/kaspi-api`** — авторизованный личный кабинет (подключение Cashier по номеру телефона + смс-код, баланс кошелька, история операций, пополнение). Это НЕ публичная страница — маршрут `/cashier-api` для нового лендинга не конфликтует.
- **`/kaspi-api/docs`** — техническая документация (эндпоинты, примеры кода). Сейчас **полностью публична, без какой-либо проверки авторизации** (обычный server-компонент, ни `'use client'`, ни `supabase.auth`, ни редиректа).
- **`/api/kaspi/pay`** — реальный API создания платежа: `POST`, заголовок `Authorization: Bearer <api_token>`, тело `{ amount, order_id, callback_url? }`, ответ `{ qr_token, payment_link, operation_id, expire_date }`. Rate limit 20 запросов/60 сек на пользователя.
- **Реальное ценообразование (уже в коде, не гипотеза):** `COMMISSION_RATE = 0.02` в `src/lib/kaspiPay/wallet.ts` — 2% с суммы каждого **проведённого** платежа, из предоплаченного баланса (`kaspi_wallet_balance` в `profiles`). Подключение Cashier само по себе бесплатно на любом тарифе. Никакой абонентской платы и минимального оборота.

## Решение о цене (принято в этом брейнсторме)

Рекламировать **уже живую** модель — 2% с оплаченного, без абонплаты. НЕ рекламировать гипотетический «5–10₸/вызов» из ценового меморандума — та модель не реализована в коде, и вводить её сейчас означает сначала строить новый биллинг, а не только лендинг. Если объём вырастет настолько, что понадобится другая модель — это отдельное решение в будущем, не часть этого проекта.

## Решение о раскрытии механизма (принято в этом брейнсторме)

Kaspi официально не даёт публичного merchant API для этого сценария — Cashier работает через тот же неофициальный протокол, что и приложение Kaspi Pay Cashier. Founder явно не хочет, чтобы конкуренты могли по документации воспроизвести сервис.

- **Лендинг** (`/cashier-api`): шаг подключения формулируется на уровне «номер телефона + смс-код, как в приложении Kaspi Pay» — этого достаточно для доверия и понимания, не раскрывает протокол. Никакого отдельного риск-дисклеймера на самой странице не нужно.
- **`/kaspi-api/docs`**: закрыть от посторонних — добавить туда ту же проверку авторизации, что уже используется на `/kaspi-api` (клиентская проверка сессии через `supabase.auth.getUser()`, редирект на `/login` при отсутствии сессии). Технические детали видны только вошедшим пользователям, не любому в интернете.

## Аудитория и тон

Разработчики и технические основатели — не тот же клиент, что у основного лендинга (ИП/ТОО, которым нужна бухгалтерия). Визуальный язык **сознательно другой**, не бренд-палитра invoices.kz (`COLOR.violet`/`teal`/`ground` из `page.tsx` здесь не используются):

- **Тёмная docs-тема**, близкая к GitHub Dark / Stripe docs: фон `#0a0c10`/`#0d1117`/`#161b22` (три уровня поверхности), текст `#c9d1d9`, приглушённый `#8b949e`, акцент успеха/кода `#7ee787`, граница `#21262d`/`#30363d`, кнопка основного действия `#238636` (зелёный, ассоциация с "запущен"/"успешно" в терминальных интерфейсах — иная семантика, чем `COLOR.violet` основного бренда, и это осознанный выбор для этой аудитории).
- **Типографика:** заголовки и обычный текст — системный sans (`-apple-system` и его цепочка), весь код и технические значения (эндпоинты, JSON, поля) — монотип (`'SF Mono', Consolas, monospace`).
- Утверждено визуально через visual companion (`hero-docs-refined.html`, `full-page-v1.html`) — направление "docs-first с вкладками языков" (вариант C из трёх предложенных), а не терминал-геро на весь экран (A) и не сплит с QR-иллюстрацией (B).

## Структура страницы (утверждена)

Один маршрут, один язык (русский — см. «Локализация» ниже), одна прокручиваемая страница, без авторизации.

### 1. Header (минимальный, НЕ DesktopShell)

Это публичная страница для анонимных посетителей (в т.ч. потенциально конкурентов) — не часть авторизованного приложения. Не переиспользует `DesktopShell`/`SiteNav` (те — для вошедших пользователей). Минимальный header: логотип/ссылка на `invoices.kz` (обратно на главный лендинг) слева, кнопка «Получить доступ к API» справа (см. CTA ниже).

### 2. Hero

Утверждённый вариант из `hero-docs-refined.html`:
- Эйбрау-строка `KASPI CASHIER API` (моно, `#7ee787`, единственное уместное использование эйбрау на этой странице — она здесь не декоративный киккер, а лейбл продукта, как на реальных API-страницах у Stripe/Twilio)
- Заголовок: «Kaspi Pay на вашем сайте — три запроса, без интеграции с банком»
- Подзаголовок: «Создание платежа, QR-ссылка и вебхук об оплате. 2% с оплаченного — без абонплаты и минимального оборота.»
- Блок с вкладками **cURL / JavaScript / Python** — переключение вживую (React `useState`, без библиотек подсветки синтаксиса — простой `<pre>` с ручной раскраской токенов через `<span>`, как в мокапе), показывающий реальный вызов `POST /api/kaspi/pay` с полями `amount`/`order_id` и реальный ответ `{ payment_link, qr_token, operation_id }`.
- Два CTA: «Получить доступ к API» (основной, зелёный `#238636`) и «Смотреть документацию» (вторичный, обводка) — оба описаны в разделе CTA ниже.

### 3. Шаги интеграции (нумерованный список — оправдан, это реальная последовательность, не декоративная нумерация)

Четыре шага, компактная grid-раскладка (4 колонки на десктопе, стек на мобильном):
1. **Подключите Cashier** — «Номер телефона + смс-код, как в приложении Kaspi Pay»
2. **Получите токен** — «API-токен и секрет вебхука — показываются один раз»
3. **Вызовите API** — «`POST /api/kaspi/pay` — получите ссылку и QR»
4. **Получите вебхук** — «Уведомление на ваш `callback_url`, когда клиент оплатит»

### 4. Цена

Крупная цифра `2%` слева («с суммы каждого оплаченного платежа. Ничего — если платежа не было.»), рядом — компактное сравнение с ApiPay.kz (реальный конкурент, публичные тарифы 10 000–60 000₸/мес по объёмному лимиту) против нашей модели без абонплаты. Формат — простое сопоставление двух строк, не таблица-простыня и не карточки.

### 5. Возможности (плотный список, НЕ карточная сетка — тот же анти-паттерн, что уже исправляли на основном лендинге)

Список из 4 пунктов, каждый — название возможности слева, соответствующее техническое значение (эндпоинт/поле) справа моноширинным шрифтом, разделены тонкой границей:
- Создание платежа → `POST /api/kaspi/pay`
- QR-код и платёжная ссылка → `payment_link, qr_token`
- Вебхук об оплате → `callback_url`
- Проверка статуса → `GET /api/kaspi/dashboard`

### 6. Финальный CTA

Заголовок «Готовы принимать Kaspi Pay?» + одна кнопка «Получить доступ к API».

### 7. Footer

Минимальный: ссылка обратно на `invoices.kz`, ссылка на `/kaspi-api/docs` (теперь закрытую авторизацией — попытка открыть без входа уводит на `/login`), копирайт-строка (переиспользовать текст из `footerBottom` основного лендинга).

## CTA-поведение

Обе кнопки «Получить доступ к API» (в hero и в финальном CTA) ведут на `/login` — **то же поведение**, что у всех CTA основного лендинга (`goLogin` → `router.push('/login')` в `page.tsx`). У `/login` сейчас нет параметра редиректа после входа (проверено — `redirectTo` в коде `/login` жёстко указывает на `/auth/callback`, без поддержки `next=`), так что после входа пользователь попадает на дефолтный пункт назначения входа (не обязательно `/kaspi-api`) — это существующее ограничение инфраструктуры входа, чинить его не входит в объём этого проекта. Кнопка «Смотреть документацию» ведёт на `/kaspi-api/docs`.

## Локализация

**Только русский язык**, без `COPY`-словаря на 3 языка, в отличие от `src/app/page.tsx`. Обоснование: аудитория страницы — разработчики, для которых техническая документация проекта (`/kaspi-api/docs`, `/kaspi-api`) уже полностью на русском без i18n; поддержка трёх языков для этой страницы — не соответствующие возврату инвестиции усилия на этом этапе. Если в будущем понадобится казахский/английский — это отдельное решение, не блокирующее запуск.

## Технические детали реализации

- Новый файл `src/app/cashier-api/page.tsx` — можно НЕ быть `'use client'`, если вкладки языка реализованы как единственный интерактивный элемент (простой `useState` в клиентском под-компоненте, остальная страница может быть статичной). Решение о ровно одном клиентском острове (переключатель вкладок) или всей странице как `'use client'` — на усмотрение реализации, не критично для дизайна.
- Framer-motion не обязателен (в отличие от основного лендинга) — это более сдержанная, docs-подобная страница; лёгкие CSS-transition для наведения на кнопки достаточно. Если используется анимация появления секций при скролле — обязательно с `prefers-reduced-motion` guard, как везде в проекте.
- Тач-таргет 44px — та же база проекта, что применена в остальных недавних правках (`a42a67b`, `366074b`) — обе CTA-кнопки и вкладки языка должны соответствовать.
- Изменение `src/app/kaspi-api/docs/page.tsx`: добавить `'use client'`, `useEffect` с проверкой `supabase.auth.getUser()`, редирект на `/login` при отсутствии пользователя — тот же паттерн, что в `src/app/kaspi-api/page.tsx:96-98`. Пока идёт проверка — короткий текстовый лоадер (тот же паттерн `Загрузка…`, что в `/kaspi-api`).

## Границы (что НЕ входит)

- Изменение реальной модели биллинга (переход на «5–10₸/вызов» или любую другую) — не в этом проекте.
- Редирект-параметр (`next=`) для `/login` — существующее ограничение, не чинится здесь.
- Казахская/английская версия страницы — не сейчас.
- Любые изменения `/kaspi-api` (личный кабинет) кроме `/kaspi-api/docs` — не трогаем.
- Ежегодная подписка / изменения `settlePlanPayment.ts` — не относится к этому проекту.
