# Kaspi Shop — репрайсер для продавцов Kaspi Магазина — дизайн

**Статус:** одобрено, готово к написанию плана.

## Проблема

invoices.kz сейчас обслуживает один сегмент — ИП/ТОО, которым нужны счета, КП, АВР, накладные. Существует отдельный, платящий рынок продавцов на Kaspi Магазине (маркетплейс Kaspi.kz), которым эти документы не нужны вовсе, но нужен инструмент, который есть у конкурентов (SaleScout, Kaskyr, AlgaTop, Boosty.kz, ibot.kz, AWW.kz) — автоматическое поддержание конкурентной цены на свои товары. Эти сервисы берут 9 990–100 000 ₸/мес в зависимости от объёма каталога, некоторые работают с 2022 года — спрос подтверждён деньгами.

## Цель

Запустить первый из нескольких запланированных инструментов для продавцов Kaspi — автоматический репрайсер: бот, который следит за ценами конкурентов на те же товары и держит цену продавца конкурентоспособной, не опускаясь ниже заданного им предела.

## Новая аудитория и позиционирование

Пользователи Kaspi Shop — новый, отдельный от текущей базы invoices.kz сегмент (продавцы на Kaspi Магазине, которым счета/КП/АВР не нужны). Несмотря на это:
- **Вход единый** — тот же аккаунт, тот же логин, что и у остального invoices.kz. Отдельной регистрации нет.
- **Раздел виден всем пользователям invoices.kz**, не только тем, кто уже подключил Kaspi Shop — новый пункт в главном меню (см. «Навигация» ниже) выступает мостом для перетекания клиентов между направлениями в обе стороны: обычный клиент invoices.kz может обнаружить, что тоже продаёт на Kaspi, а продавец Kaspi может обнаружить, что ему нужны счета для B2B-клиентов.
- Технически всё в том же Next.js-проекте и той же базе Supabase — новые таблицы, не новая инфраструктура.

## Навигация

Главное меню сейчас — три пункта, отрисовываются из одного массива `items` в `src/components/AppNav.tsx` (и на нижней панели мобильной версии, и на десктопном сайдбаре): Создать (`/dashboard`), История (`/history`), Профиль (`/profile`). Добавляется четвёртый, равноправный пункт — **«Kaspi Магазин»** → новый роут верхнего уровня `/kaspi-shop` (не под `/profile`), со своей иконкой, по тому же паттерну, что и три существующих.

## Подключение продавца

Продавец сам генерирует API-токен в своём кабинете продавца на Kaspi (Настройки → Токен API → Сформировать — задокументированный, официальный механизм Kaspi для партнёров, guide.kaspi.kz/partner) и вставляет его на странице подключения `/kaspi-shop`. Токен хранится зашифрованным (тот же подход, что уже используется для данных подключения Kaspi Pay Cashier — AES-256-GCM at rest). Никакого обхода защиты, никакой автоматизации логина/OTP — просто ключ, который Kaspi сам выдаёт официально через партнёрский кабинет.

## Отслеживаемые товары

После подключения сервис запрашивает каталог продавца через официальный Kaspi Goods API. Продавец на странице `/kaspi-shop` отмечает нужные товары и задаёт на каждый:
- **Минимальную цену (пол)** — вручную вводимое число, бот никогда не уйдёт ниже.
- **Шаг/отступ** — на сколько тенге или процентов быть ниже цены конкурента (задаёт сам продавец, не жёстко «на 1 тенге», как у большинства конкурентов).
- **Частоту проверки** — настраивается по каждому товару отдельно (например, чаще для ходовых позиций, реже для остальных — экономия кредитов).

## Логика репрайсинга

На каждом цикле проверки для товара:
1. Читаем публичную страницу товара на Kaspi.kz — там всегда видны предложения всех продавцов с ценами (публичные данные, не приватный доступ).
2. Берём самую низкую цену среди конкурентов (не считая самого продавца).
3. Считаем кандидата: `цена_конкурента − шаг_продавца`.
4. Если кандидат ≥ пола — обновляем цену через официальный Kaspi Merchant API.
5. Если кандидат < пола — **держим цену на уровне пола**, дальше не демпингуем, и отправляем уведомление в Telegram (тот же бот/паттерн, что уже используется в проекте) — продавец сам решает, снижать ли пол вручную.

## Планировщик

Vercel Hobby (бесплатный план, на котором сейчас работает invoices.kz) даёт запускать фоновые задачи (cron) не чаще раза в сутки — этого недостаточно для репрайсинга, который у конкурентов обновляется каждые 5–15 минут. Решение: бесплатный внешний планировщик (например, GitHub Actions по расписанию в этом же репозитории) дёргает новый API-эндпоинт каждые 5–15 минут; эндпоинт сам вычисляет, каким товарам каких продавцов пора на проверку, исходя из их индивидуальной частоты. Эндпоинт защищён внутренним секретом (тот же паттерн, что `IG_AUTOMATION_SECRET` для Instagram-вебхука), а не публично открыт.

## Кредиты и биллинг

Отдельный кошелёк **Kaspi Shop Wallet** — не тот же, что уже существует для Kaspi Pay Cashier (там деньги за приём платежей, здесь — за проверки цен, разная природа списаний, смешивать нельзя, иначе клиент не поймёт, за что списалось).
- **1 кредит = 5 ₸** при пополнении.
- **1 цикл проверки/обновления цены = 1 кредит**, списывается при КАЖДОМ выполненном цикле независимо от результата (`updated`/`held_at_floor`/`no_change`/`error`) — сама проверка цены конкурента уже работа и уже стоит денег, вне зависимости от того, потребовалось ли реальное обновление или запрос к Kaspi API упал с ошибкой после сравнения цен.
- Пополнение — через Kaspi Pay, тем же UI-паттерном, что уже работает для пополнения кошелька Kaspi Pay Cashier, только зачисление идёт в Kaspi Shop Wallet.

## Уведомления и безопасность

- **Общий выключатель паузы** на всё подключение (тот же паттерн, что `instagram_autoreply_settings.paused`) — останавливает все проверки/обновления разом.
- **Переключатель на каждый товар** — включить/выключить отслеживание отдельно, не трогая остальные.
- Уведомление в Telegram при упоре в пол (см. «Логика репрайсинга»).

## Модель данных

**`kaspi_shop_connections`** — подключение продавца к Kaspi:
- `id` uuid pk, `user_id` uuid, `api_token` text (зашифрован), `status` text (`active`/`error`), `paused` boolean default false, `created_at`, `last_checked_at`

**`kaspi_shop_tracked_products`** — отслеживаемые товары:
- `id` uuid pk, `connection_id` uuid, `user_id` uuid, `kaspi_product_id` text, `product_name` text, `own_current_price` numeric, `floor_price` numeric, `undercut_step` numeric, `check_frequency_minutes` int, `enabled` boolean default true, `last_checked_at`, `last_competitor_price` numeric, `created_at`

**`kaspi_shop_price_checks`** — журнал проверок (источник для списания кредитов и истории):
- `id` uuid pk, `tracked_product_id` uuid, `checked_at`, `competitor_price` numeric, `own_price_before` numeric, `own_price_after` numeric, `action` text (`updated`/`held_at_floor`/`no_change`/`error`), `credit_cost` int

**`kaspi_shop_wallet`** — баланс:
- `id` uuid pk, `user_id` uuid, `balance` numeric

**`kaspi_shop_wallet_ledger`** — история списаний/пополнений:
- `id` uuid pk, `wallet_id` uuid, `user_id` uuid, `amount` numeric, `type` text (`topup`/`check_debit`), `note` text, `created_at`

Все новые таблицы — RLS enabled, без клиентских policy (service-role only), по установившемуся в проекте паттерну для приватных финансовых/интеграционных данных (`kaspi_connections`, `instagram_auto_replies` и т.д.) — доступ только через собственные API-роуты с проверкой владельца.

## Вне рамок (для будущих подпроектов, не сейчас)

- **Калькулятор маржи** с учётом комиссии Kaspi по категориям — отдельный подпроект.
- **Поиск ниш / анализ спроса** — отдельный подпроект, требует своего исследования (например, у AlgaTop база из 15М товаров).
- **Аналитика продаж** — отдельный подпроект.
- **WhatsApp-рассылки** — отдельный подпроект, есть у AlgaTop как одна из фич.
- **Налоговая декларация и оплата налогов** — отдельное, будущее направление, зависит от интеграции с БЦК (сейчас на паузе, ждём ответа от банка) — не часть Kaspi Shop.
- Точный процент комиссии Kaspi по категориям — не исследован в этой сессии, не нужен для репрайсера (только для будущего калькулятора маржи).
- Точная механика/эндпоинт официального API обновления цены — общая механика подтверждена (есть Merchant API, генерация токена, задокументированные Orders/Goods эндпоинты), но точные параметры price-update запроса не были получены в ходе исследования в этой сессии — уточнить при написании плана реализации, до начала кодирования.
