# AI-агент — поддержка фото и голосовых сообщений — Design

**Status:** approved section-by-section with the user in live dialogue (2026-08-23), each section confirmed before moving to the next.

## Обзор

Сейчас во всех трёх каналах AI-агента (WhatsApp, Telegram, Instagram DM) сообщение, у которого нет текста — фото, голосовое, видео, документ, стикер, геолокация — **молча отбрасывается**: клиент не получает вообще никакого ответа. Подтверждено чтением кода всех трёх вебхук-роутов (`msg.type !== 'text'` / `!msg?.text` → `continue`).

Источник задачи — конкурентная разведка 2026-08-22 (`docs superpowers/specs` не касается, отчёт опубликован как Artifact): у Kelesu (прямой конкурент AI-агента) есть распознавание голоса (Whisper) и фото/документов. Это реальный, а не гипотетический пробел.

**Что делаем:**
- **Голосовые** → скачиваются с платформы → транскрибируются через OpenAI Whisper → полученный текст течёт **как обычное текстовое сообщение** через весь существующий пайплайн (шаблоны, история, обучающий режим, очередь на проверку) без изменений в этой логике.
- **Фото** → скачиваются → передаются в Claude как image-блок (Claude поддерживает зрение нативно, смена модели не нужна). Подпись к фото (если есть) идёт текстом рядом. Поиск по шаблонам для фото **пропускается** — совпадение по словам не имеет смысла, когда смысл сообщения в картинке.
- **Всё остальное** (видео, документы, стикеры, геолокация, контакты, и любая ошибка на любом шаге выше) → один вежливый статический ответ («Пока не умею обрабатывать такой тип сообщения — опишите, пожалуйста, текстом 🙂»), без вызова ИИ, без списания с кошелька — как бесплатный шаблонный ответ.

## Область применения

Только мультитенантный **AI-агент** (WhatsApp/Telegram/Instagram-каналы клиентов invoices.kz — `src/lib/aiAgent/*`). Старый одиночный Instagram-бот (`instagram-comments-dm-autoreply`, `src/app/api/instagram/webhook/route.ts`'s `isLegacyAccount` ветка) **не трогаем** в этой итерации — его вебхук-роут не обновляется, хотя он и делит `generateAiReply` с AI-агентом.

Голос и фото — на все три канала сразу (не по одному), так как логика одинаковая во всех трёх обработчиках, разница только в скачивании медиа-файла с конкретной платформы.

## Биллинг

Тот же 5₸ (1 кредит) за ИИ-ответ, что и за обычный текстовый — фото/голос не дороже. Стоимость транскрибации Whisper (~3₸/мин, типичное голосовое < 1₸) укладывается в существующую маржу, отдельно не считается и не отображается. Канальный fallback-ответ на нераспознанный тип — бесплатный, как совпадение по шаблону.

## Новая зависимость

`OPENAI_API_KEY` (OpenAI Whisper API, модель `whisper-1`) — первый сторонний ИИ-вендор в проекте помимо Anthropic. Нужен в `.env.local`, затем в Vercel Production + редеплой (как и с каждым прошлым внешним сервисом в этом проекте — см. `[[bcc-connect-v2-invoices-kz]]`, `[[kaspi-pay-cashier-invoices-kz]]`).

## Архитектура и поток данных

### Скачивание медиа — своя функция на канал (API у платформ разные)

- **WhatsApp** (`src/lib/whatsapp.ts`, новая `downloadWhatsAppMedia(mediaId, accessToken)`): `GET /{media-id}` (Graph API) → временный `url` в ответе → `GET` этого `url` с тем же Bearer-токеном → бинарь + `mime_type` из первого ответа.
- **Telegram** (`src/lib/aiAgent/telegram.ts`, новая `downloadTelegramMedia(fileId, botToken)`): `getFile` → `file_path` → `GET https://api.telegram.org/file/bot{token}/{file_path}` → бинарь. Фото: `message.photo` — массив размеров, берём последний (наибольшее разрешение) элемент по `file_id`; Telegram Bot API всегда переупаковывает фото в JPEG, `mediaType` для фото с этого канала — жёстко `image/jpeg` (в ответе `getFile` своего mime type нет). Голос: `message.voice.file_id`, формат ogg/opus.
- **Instagram**: проще всех — вложение в DM (`messaging[].message.attachments[]`) уже содержит готовый подписанный CDN `payload.url`, скачивается напрямую `GET`-запросом без обмена токена. Тип определяется по `attachments[].type` (`image` / `audio`).

Whisper поддерживает ogg/oga нативно — конвертация формата не нужна ни для одной из трёх платформ (все шлют голосовые в ogg/opus).

### Классификация — на уровне вебхук-роута, не в общем обработчике

В каждом из трёх роутов (`src/app/api/whatsapp/webhook/route.ts`, `src/app/api/ai-agent/telegram/webhook/route.ts`, `src/app/api/instagram/webhook/route.ts`, только не-legacy ветка) — там, где сейчас `continue` на нетекстовом сообщении, добавляется классификация по типу:

1. **Фото** → скачать → base64 → вызвать обработчик с `media: {kind:'image', base64, mediaType}`, `incomingText` = подпись или `«[Фото]»`, если подписи нет.
2. **Голос** → скачать → `transcribeAudio()` (новый `src/lib/openaiWhisper.ts`) → вызвать обработчик как обычное текстовое сообщение (`incomingText` = транскрипт), без `media`.
3. **Всё остальное / любая ошибка на шаге 1-2** → статический ответ напрямую с роута (`sendWhatsAppMessage`/`sendTelegramBotMessage`/`sendDirectMessage` с готовым текстом), без вызова `generateAiReply`, без записи в `ai_agent_messages`, без списания.

### `generateAiReply` (`src/lib/instagramAiReply.ts`) — новый необязательный `image`-параметр

```ts
image?: { base64: string; mediaType: string }
```

Когда передан — в `content` Anthropic-сообщения добавляется image-блок (`{type:'image', source:{type:'base64', media_type, data: base64}}`) перед текстовым блоком. Отсутствует — поведение и промпт побайтово те же, что сейчас (тот же принцип обратной совместимости, что уже применён к `collectFieldsToExtract`).

### Три обработчика — новый необязательный `media`-параметр

`handleWhatsAppIncoming` / `handleTelegramIncoming` / `handleTenantIncoming` (Instagram, `webhookHandler.ts`) каждый получают необязательный параметр:

```ts
media?: { kind: 'image'; base64: string; mediaType: string }
```

Если передан — шаг поиска по шаблонам пропускается, `media` пробрасывается в `generateAiReply` как `image`. Вся остальная логика (дедуп, обучающий режим, кошелёк, история) не меняется.

### Защитные лимиты

Проверяются **после скачивания**, по фактическому размеру полученного буфера — метаданные о размере до скачивания не единообразно доступны на всех трёх платформах (Instagram-вложение не даёт размер заранее), поэтому единая точка проверки — уже скачанные байты, а не ответ API со ссылкой на файл:

- Фото крупнее ~4 МБ (предел base64-картинки у Claude) → тот же вежливый fallback, не падение.
- Голос длиннее лимита Whisper (~25 МБ файла) → тот же fallback.
- `mediaType` фото не входит в принимаемый Claude список (`image/jpeg`, `image/png`, `image/gif`, `image/webp`) → тот же fallback вместо отправки заведомо отклоняемого запроса в Anthropic.

## Обработка ошибок

Любая ошибка на любом шаге (скачивание не удалось, Whisper недоступен, файл повреждён, превышен лимит размера) → единый вежливый статический ответ + `console.error` с деталями. Ошибка на одном сообщении никогда не должна прерывать обработку остальных сообщений в том же вебхук-пакете — тот же принцип, что уже используется во всех трёх роутах сейчас.

## Очередь на проверку / обучающий режим

Изменений не требует. Голос к моменту записи в `ai_agent_messages` уже обычный текст. Для фото `incomingText` (подпись или `«[Фото]»`) уже осмысленно отображается в существующей вёрстке (`item.question` на `/ai-agent/review`). Показ миниатюры самой картинки в очереди — явно не входит в объём этой итерации.

## Тестирование

По уже принятому в проекте правилу: сетевые вызовы (Whisper, скачивание медиа с трёх платформ) остаются без тестов — как и сам `generateAiReply` сейчас (см. комментарий в начале файла). Чистая логика — classification-функция «какой тип сообщения» и проверка лимита размера — получает colocated-тесты.

## Явно не входит в объём

- Старый одиночный Instagram-бот (`instagram-comments-dm-autoreply`) — вебхук не обновляется.
- Миниатюра фото в очереди на проверку.
- Видео, документы, стикеры, геолокация — только вежливый текстовый fallback, не обработка содержимого.
- Раздельный биллинг/индикация стоимости для медиа-ответов в кошельке (см. `[[ai_agent_feature_invoices_kz]]`, `#3` уже сделан отдельно).

## Порядок реализации (~10-11 задач, subagent-driven-development)

1. `src/lib/openaiWhisper.ts` — новый модуль транскрибации (+ тест на чистую логику, если есть)
2. `whatsapp.ts` — `downloadWhatsAppMedia`
3. `telegram.ts` — `downloadTelegramMedia` + разбор апдейта на photo/voice/other
4. `instagramAiReply.ts` — `generateAiReply` получает `image`-параметр
5. `whatsappWebhookHandler.ts` — принимает и прокидывает `media`
6. `telegramWebhookHandler.ts` — то же
7. `webhookHandler.ts` (Instagram, tenant-ветка) — то же
8. `src/app/api/whatsapp/webhook/route.ts` — классификация типа + скачивание/Whisper + fallback-ответ
9. `src/app/api/ai-agent/telegram/webhook/route.ts` — то же
10. `src/app/api/instagram/webhook/route.ts` (только не-legacy ветка) — то же
11. Финальный сквозной ревью + `tsc --noEmit` + `npm run build`
