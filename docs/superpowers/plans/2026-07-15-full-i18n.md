# Full Application i18n (ru/kk/en) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Translate the entire application (except `/privacy` and `/terms`, deferred) into Russian, Kazakh, and English, with a working 3-way language switcher.

**Architecture:** Widen the existing `Lang` type to `'ru' | 'kk' | 'en'`. Add one dictionary file per translated page under `src/lib/i18n/`, each exporting `Record<Lang, T>` for a page-specific interface, mirroring the existing `src/lib/i18n/landing.ts` pattern. Each page imports `useLanguage()` (already provided by `src/components/LanguageProvider.tsx`) and reads `dict[lang]`.

**Tech Stack:** Next.js App Router, TypeScript, React Context (existing `LanguageProvider`) — no new dependencies, no i18n library, no URL-based locale routing.

## Global Constraints

- Every new dictionary's `ru` values must be **copied verbatim** (byte-identical) from the string currently hardcoded in the page — this is a zero-behavior-change requirement for existing Russian users. Do not "improve" or reword the Russian text.
- `kk` and `en` translations are done by the implementing agent to a good-faith standard (this codebase has no native-speaker review step for translations — out of scope per the spec).
- Alerts and `confirm()` dialogs are in scope — they are user-facing text.
- Any string built with a template literal / concatenation (e.g. `` `Счёт №${n} отправлен` ``) becomes a **function** in the dictionary (e.g. `invoiceSentMessage: (n: string) => \`Invoice #${n} sent\``), not a plain string, so interpolation keeps working per language. Static strings stay plain strings.
- Dictionary key names describe what the string is (`saveButton`, `deleteConfirm`), never where it sits in the page.
- Do not touch `/privacy` or `/terms` — explicitly deferred.
- Do not introduce `next-intl`, `react-i18next`, or any URL locale prefix (`/en/...`) — would break existing invoice links (`/view/[token]`) and other shared URLs.
- After each task: run `npx tsc --noEmit` (must be 0 errors) — this codebase has no unit tests for UI/page text (only `plan.test.ts`/`webhookSignature.test.ts` test pure logic), so typecheck is the verification bar, plus a manual visual check switching between all 3 languages on the affected page(s).
