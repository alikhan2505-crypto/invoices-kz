# Шаблоны писем Supabase Auth

Supabase хранит шаблоны только в панели и ничего не версионирует. Файлы здесь —
единственная копия, по которой шаблон можно просмотреть, отревьюить и
восстановить, если его случайно затрут.

**Изменили шаблон в панели — обновите файл здесь.** Иначе копии разойдутся, и
через месяц будет непонятно, какая из них настоящая.

## magic-link.html

Единственное письмо, которое реально уходит пользователям: вход в приложение
сделан через `signInWithOtp` (`src/app/login/page.tsx`), и та же ссылка
обслуживает и первый вход, и регистрацию. Пароля в продукте нет, поэтому
шаблонов сброса пароля и подтверждения регистрации в потоке не существует.

Куда вставлять: **Supabase → Authentication → Emails → Magic Link**.

Тема письма (поле Subject, там же):

```
invoices.kz — ссылка для входа · кіру сілтемесі · sign-in link
```

Русский в теме стоит первым не по важности языков, а из-за обрезки: мобильная
почта показывает около 35 символов, и при казахском впереди большинство
получателей увидело бы только его. В теле письма порядок обратный —
казахский, русский, английский.

## Имя отправителя

Задаётся отдельно от шаблона: **Supabase → Authentication → Emails → SMTP
Settings → Sender name**. Сейчас там `INVOICES.KZ`.

До 10.09.2026 письма уходили от имени **«Данияр»** — постороннее человеческое
имя на письме со ссылкой для входа выглядит как фишинг, и часть получателей по
такой ссылке не пойдёт. Имени нет ни в коде, ни в шаблоне: оно берётся только
из этой настройки.

## Как проверить, что получилось

Запросить вход на любой свой адрес и посмотреть, что реально ушло:

```
POST {SUPABASE_URL}/auth/v1/otp   apikey: <anon>   {"email":"...","create_user":false}
GET  https://api.resend.com/emails?limit=2        Bearer $RESEND_READ_API_KEY
GET  https://api.resend.com/emails/{id}           — вернёт html целиком
```

Проверено так 10.09.2026: `from` = `"INVOICES.KZ" <mail@invoices.kz>`, тема —
строка выше, в теле три блока (Қазақша / Русский / English) и три ссылки для
входа, стандартной рыбы Supabase не осталось.

Учтите ограничение `Minimum interval per user` (60 секунд) — второй запрос на
тот же адрес подряд не уйдёт.

## Что сейчас стоит в панели (04.11.2026)

- **Confirm sign up** (новому адресу): `confirm-signup-with-code.html`, тема `invoices.kz — подтвердите почту · поштаны растаңыз · confirm your email`.
- **Magic link or OTP** (вернувшемуся; в панели раздел называется так, адрес `/auth/templates/magic-link-or-otp`): `magic-link-with-code.html`, тема прежняя.
- **Sign In / Providers → Email**: длина кода (Email OTP length) **8**, срок 3600 с. Страница входа ждёт ровно 8 цифр (`OTP_LENGTH` в `src/app/login/page.tsx`): поменяли длину в панели, поменяйте и там.
- Вход по коду включён (`LOGIN_CODE_ENABLED = true`). Проверено 04.11 на проде: письмо входа тестовому аккаунту пришло с 8-значным кодом, код из письма впускает (verifyOtp type 'email'), на экране входа неверный код даёт ошибку, верный впускает сам после восьмой цифры. Письмо Confirm sign up с кодом вживую не проверялось (для этого нужна новая регистрация); код в нём проверяется как 'signup'.
- Сверить панель с файлами: в редакторе панели `monaco.editor.getModels()[0].getValue()`, sha256 после замены CRLF на LF должен совпасть с файлом.

## magic-link-with-code.html (03.11.2026, вставлен 04.11.2026)

То же письмо плюс код (8 цифр) под кнопкой. Нужен, чтобы войти, когда ссылка из письма открылась не в том
браузере: письмо читают в почтовом приложении, а вход начинался во встроенном браузере Instagram, и сессия
оставалась там. Код человек вводит на той же странице входа.

Включение: вставить файл в Supabase → Authentication → Emails → Magic Link, проверить длину кода (8) и срок
(3600 с), затем в `src/app/login/page.tsx` поменять `LOGIN_CODE_ENABLED` на `true` и выкатить. До этого поле
для кода на странице входа скрыто, а действующий шаблон остаётся `magic-link.html`.

## confirm-signup.html (03.11.2026; 04.11.2026 заменён вариантом с кодом)

**Первое письмо, которое получает новый человек.** Новому адресу Supabase шлёт не Magic Link, а «Confirm signup»
(Authentication → Emails → Confirm signup): старая запись в этой папке («единственное письмо, которое стоит
трогать») была неверной. В панели там старое письмо «Добро пожаловать!» с четырьмя пунктами без единой ссылки на то,
что сделано с сентября. Новое: тот же вид, что у Magic Link, кнопка подтверждения, список того, что работает
сейчас (счёт, проверка по БИН и бот, бесплатные инструменты, Kaspi Bot, ИИ-агент, разборы) со ссылками на каждый
пункт, внизу Instagram и Telegram. Тема письма (поле Subject там же):

```
invoices.kz — подтвердите почту · поштаны растаңыз · confirm your email
```

Файлы с кодом (`confirm-signup-with-code.html`, `magic-link-with-code.html`) вставляются ПАРОЙ: новому человеку
уходит одно письмо, вернувшемуся другое, и код нужен в обоих. Только после этого `LOGIN_CODE_ENABLED = true`.
`magic-link.html` в этой же правке получил обновлённую строку «что внутри» и ссылки на Instagram и Telegram.
