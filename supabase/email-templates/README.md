# Шаблоны писем Supabase Auth

Supabase хранит шаблоны только в панели и ничего не версионирует. Файлы здесь —
единственная копия, по которой шаблон можно просмотреть, отревьюить и
восстановить, если его случайно затрут.

**Изменили шаблон в панели — обновите файл здесь.** Иначе копии разойдутся, и
через месяц будет непонятно, какая из них настоящая.

## magic-link.html

Единственное письмо, которое реально уходит пользователям: вход в приложение
сделан через `signInWithOtp` (`src/app/login/page.tsx`), и та же ссылка
обслуживает и первый вход, и регистрацию. Пароля в продукте нет, поэтому
шаблонов сброса пароля и подтверждения регистрации в потоке не существует.

Куда вставлять: **Supabase → Authentication → Emails → Magic Link**.

Тема письма (поле Subject, там же):

```
invoices.kz — ссылка для входа · кіру сілтемесі · sign-in link
```

Русский в теме стоит первым не по важности языков, а из-за обрезки: мобильная
почта показывает около 35 символов, и при казахском впереди большинство
получателей увидело бы только его. В теле письма порядок обратный —
казахский, русский, английский.

## Имя отправителя

Задаётся отдельно от шаблона: **Supabase → Authentication → Emails → SMTP
Settings → Sender name**. Сейчас там `INVOICES.KZ`.

До 10.09.2026 письма уходили от имени **«Данияр»** — постороннее человеческое
имя на письме со ссылкой для входа выглядит как фишинг, и часть получателей по
такой ссылке не пойдёт. Имени нет ни в коде, ни в шаблоне: оно берётся только
из этой настройки.

## Как проверить, что получилось

Запросить вход на любой свой адрес и посмотреть, что реально ушло:

```
POST {SUPABASE_URL}/auth/v1/otp   apikey: <anon>   {"email":"...","create_user":false}
GET  https://api.resend.com/emails?limit=2        Bearer $RESEND_READ_API_KEY
GET  https://api.resend.com/emails/{id}           — вернёт html целиком
```

Проверено так 10.09.2026: `from` = `"INVOICES.KZ" <mail@invoices.kz>`, тема —
строка выше, в теле три блока (Қазақша / Русский / English) и три ссылки для
входа, стандартной рыбы Supabase не осталось.

Учтите ограничение `Minimum interval per user` (60 секунд) — второй запрос на
тот же адрес подряд не уйдёт.
